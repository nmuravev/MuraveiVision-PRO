# Предложение по реализации: Фаза 1 — Интеграция DA3 (Depth Anything 3) Dense Backend

## 1. Обзор архитектуры и цели Фазы 1

Цель Фазы 1 — добавить в комплекс MuraveiVision PRO альтернативный быстрый нейросетевой бэкенд плотной 3D-реконструкции на базе модели **Depth Anything 3 (DA3)** в режиме *pose-conditioned* с привязкой к позам камер COLMAP (`camera_poses.json`).

Ключевые свойства решения:
- **Ускорение:** сокращение времени плотной реконструкции с десятков минут (AliceVision MVS) до десятков секунд при сопоставимой или превосходящей связности геометрии.
- **Двухуровневая лицензия и безопасность:**
  - Дефолтный нейросетевой бэкенд: **DA3-BASE** (лицензия Apache 2.0, свободная).
  - Опциональный высокоточный бэкенд: **DA3-LARGE** (лицензия CC BY-NC 4.0, non-commercial opt-in с предупреждающей плашкой в интерфейсе).
- **Строгая Air-Gap изоляция:** Веса размещаются исключительно в каталоге `sidecars/da3/` (только FullKit-пак). При отсутствии весов возвращается HTTP 503 `DA3_WEIGHTS_NOT_FOUND` с русскоязычным баннером в UI без сетевых попыток загрузки.
- **Инвариантность формата:** Выходным артефактом остаётся стандартный `dense.ply` в каталоге задачи `archive/recon/{job_id}/`, что обеспечивает прозрачную работу лучевой трассировки (raycast) в Inspector и переключение вьюера Flight3D.

## 3. Архитектурные детали реализации

### 3.1. Схема Pose-Conditioned Pipeline (`da3_pipeline.py`)
1. **Preflight & Gate:**
   - Проверка числа сопоставленных камер в `camera_poses.json`. Если число валидных кадров `< 8` — мягкий аборт с русскоязычным предупреждением в манифесте: `«Недостаточно зарегистрированных ракурсов COLMAP (<8) для нейросетевой реконструкции»`. Результаты COLMAP SfM остаются полностью нетронутыми.
2. **Оконная обработка (Windowed Processing):**
   - Разбиение последовательности кадров на скользящие окна по 48–64 вида с перекрытием (overlap ≈ 8–12 видов) для предотвращения исчерпания VRAM на 8 ГБ GPU.
3. **Scale Alignment (Масштабирование к метрике):**
   - Карты относительной глубины DA3 масштабируются к метрическому облаку `sparse_points.json` методом медианного выравнивания глубин по опорным 3D-точкам COLMAP.
4. **Overlap-Fusion & Очистка выбросов:**
   - Обратная проекция (unprojection) во всемирные координаты с фильтрацией по взаимной геометрической согласованности между перекрывающимися окнами.
   - Запись результата в `archive/recon/{job_id}/dense.ply`.
   - Обновление `manifest.json`: установка `"dense_backend": "da3_base"` (или `"da3_large"`), сохранение флага готовности артефакта.

### 3.2. Потоковое вещание статуса (`/api/recon/stream`)
Во время выполнения DA3 поток `/api/recon/stream` получает структурированные события:
- Стадия 1: `stage="da3_depth"`, `phase="da3_dense"`, метрики: обработано кадров / всего кадров, VRAM.
- Стадия 2: `stage="da3_fusion"`, `phase="da3_dense"`, метрики: слияние облаков точек, отсечение шума.
- Завершение: статус `colmap_done`, в манифесте активен артефакт `dense`.

### 3.3. Лицензионное разделение в интерфейсе
- Переключатель плотного бэкенда в карточке Flight3D:
  1. `AliceVision MVS` (классический фотограмметрический MVS, MPL-2.0).
  2. `DA3-BASE (Рекомендуемый)` (нейросетевой, быстрый, лицензия Apache 2.0).
  3. `DA3-LARGE (SOTA)` (нейросетевой сверхвысокой детализации, CC BY-NC 4.0 — при выборе отображается янтарный бейдж `[Non-Commercial Only]`).

## 4. План тестирования (Test Plan)

1. **Unit-тесты (`backend/tests/test_da3_pipeline.py`):**
   - Тест отсутствия весов: попытка запуска без файлов в `sidecars/da3/` вызывает контролируемую ошибку 503 `DA3_WEIGHTS_NOT_FOUND`.
   - Тест софт-фейла: передача `camera_poses.json` с 5 ракурсами приводит к корректному останову без удаления COLMAP.
   - Тест масштабирования: синтетические карты глубин корректно выравниваются по масштабу разреженного облака.
   - Тест экспортёра: формирование валидного бинарного заголовка PLY с полями `x, y, z, red, green, blue`.
2. **Интеграционный тест стриминга:**
   - Проверка эмиссии событий `da3_depth` и `da3_fusion` в очередь событий `recon_scanner`.
3. **CI / Smoke-тест:**
   - Добавление сценария в `scripts/ci_full.ps1` и smoke-прогона с мок-моделью.
4. **Фронтенд и TypeScript:**
   - Прохождение `npx tsc --noEmit` без ошибок.
   - Проверка рендеринга переключателя и NC-плашки в `Flight3D.tsx`.

## 6. Открытые вопросы (Open Questions)

1. **Формат поставки весов DA3:** Предпочтителен ли единый чекпоинт PyTorch `.pt` или `.safetensors` для безопасной десериализации без `torch.load(weights_only=True)`?
2. **Разрешение входных кадров в окне инференса:** Рекомендуется ли ограничивать максимальную длинную сторону кадра до 1024 px для гарантированного укладывания батча в 8 ГБ VRAM на видеокартах класса RTX 3060/4060 Laptop?
3. **Механизм генерации нормалей:** Генерировать ли нормали точек (`nx, ny, nz`) сразу на этапе обратной проекции DA3 для облегчения последующего построения меша или ограничиться `xyz + rgb` для минимизации размера `dense.ply`?
4. **Сохранение intermediate карт глубин:** Сохранять ли сырые карты глубин каждого кадра (`.npy` в `archive/recon/{job_id}/da3/depths/`) для повторной фильтрации, либо удалять их после генерации `dense.ply` для экономии места на диске?
